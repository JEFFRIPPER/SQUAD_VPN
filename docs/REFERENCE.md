# SQUAD VPN — подробности

Кратко о проекте — в [README](../README.md).

## Что умеет программа

Панель SQUAD VPN в том же стиле Glass MD3, что и SQUAD-VPN.apk: красно-чёрный
фон с плавающими пятнами, полупрозрачные «стеклянные» карточки.
Окно без системной рамки Windows: свой заголовок, за который оно
перетаскивается, двойной щелчок разворачивает на весь экран (панель задач
остаётся видна), справа «Свернуть», «Развернуть», «Закрыть»; размер
меняется за края. Анимации MD3 на пружинной физике: переходы между
разделами, индикатор меню, волна (ripple) и упругое нажатие кнопок,
переключатели, кнопка-эмблема как в apk (тянется за курсором, её можно
оттянуть, и она пружиной возвращается; при подключении светится, пускает
волны и оживает видео). Если в Windows выключены анимации, они выключаются и здесь.


- **VPN** — главный экран как в apk: кнопка, статус, карточка «Следующий
  сервер» / «Сервер», переключатель подписок «Топ-10 / Лучшие 300 / Белые
  списки», пинг, сессия, скорость с графиком, события. Трафик Windows идёт
  через лучшие серверы, проверенные из твоей сети. Каждые 15 секунд
  проверяется ping текущего сервера; если он перестал отвечать или стал втрое
  медленнее — переход на лучший («Авто»). Итоги за день и неделю,
  автоподключение.
- **Обзор** — работает ли программа, живые серверы, средний ping, последнее
  обновление, пробники по странам; «Обновить серверы», «Проверить обновления».
- **Подписки** — все профили с числом серверов; ссылки «откуда угодно» (GitHub)
  или «этот компьютер»; кнопки «Копировать» и **QR-код** для телефона.
- **Серверы** — выбор сервера, как в apk: «Авто — лучший сервер» и список
  серверов подписки, «Проверить пинг» (без VPN — быстрый TCP-стук, 24
  сервера сразу, до 3 с на сервер; при подключении — через ядро), «По
  пингу», «Скрыть неотвечающие». Выбрать можно и до подключения, выбор
  запоминается. Ниже, в свёрнутом блоке, подробная таблица с ping, jitter,
  score и статусом по странам.
- **Настройки** — автозапуск, автообновление, интервал проверки, страна
  компьютера, доступ с телефона по Wi-Fi, ключи доступа, резервные копии.
- **Журнал** — «Проверить систему» с кнопками исправления и журналы работы.

### VPN-клиент: важно знать

- Работает через системный прокси Windows (`127.0.0.1:7890`), права
  администратора не нужны. Браузеры и большинство программ его используют;
  игры и программы, которые игнорируют системный прокси, идут напрямую.
- Прежние настройки прокси сохраняются и возвращаются ровно такими, какими
  были. Если программа упала, фоновая часть или следующий запуск вернут их
  сами; в крайнем случае — «Журнал → Проверить систему → Вернуть прокси».
- Не включай одновременно с другим VPN на этом же компьютере.

### Телефон по Wi-Fi

«Настройки → Ключи доступа → Новый ключ» (права «только подписки»), включи
«Доступ с телефона по Wi-Fi», «Сохранить и перезапустить». При создании
ключа появится QR-код: телефон в той же сети получит подписку прямо с
компьютера — с серверами, проверенными из твоей сети. Windows может спросить
разрешение для Python в брандмауэре: разреши для частных сетей.

## Как это работает

```
источники (GitHub-фиды)
   └─ collect: загрузка, разбор, дедупликация, равномерная выборка
       └─ validate: Mihomo проверяет серверы (ping до generate_204), страну и ASN
           └─ cleanup: убирает пропавшие из источников, мёртвые перепроверяет реже
               └─ export: smart-профили → plain / base64 / Clash YAML
                   └─ publish: ветка subs на GitHub (постоянные ссылки)
```

Цикл выполняется в двух местах:

- **GitHub Actions** (`.github/workflows/update-subs.yml`) — каждый час
  (два слота: :17 и :47), проверяет из облака и публикует ветку `subs`.
  База с историей переносится через кэш Actions. Если запуск упал,
  создаётся issue `squad-alert` (GitHub пришлёт письмо), после успешного
  запуска оно закрывается само. GitHub выключает расписание, если в
  репозитории 60 дней нет активности: тогда включи его снова во вкладке
  Actions.
- **Фоновая программа на компьютере** (агент) — проверяет из твоей сети.

### Как отсеиваются нерабочие серверы

1. **Пинг** через Mihomo (`generate_204`).
2. **Реальная загрузка**: через каждый ответивший сервер скачивается 200 КБ.
   Сервер, который отвечает на пинг, но зависает на передаче (типичная
   блокировка в России — обрыв после ~16 КБ) или перегружен, считается
   мёртвым. Отключить: `--download-bytes 0`.
3. **Маскировка** (`require_tls`): голый Shadowsocks и VMess/VLESS без TLS в
   основные подписки не попадают — в России их режет DPI.
4. **История** (`min_checks`, stability): одна удачная проверка не в счёт.
5. **Скорость** загрузки замеряется у каждого сервера (сглаженно): `top` и
   `best` отсекают медленные (в `best` — от 1 Мбит/с).
6. **Источники, проверенные из России** (`ru-checked`) идут первыми.
7. **Сети, которые часто режут из России** (Hetzner, OVH, DigitalOcean,
   Cloudflare и др., `deprioritize_asns`) идут в конец списка.
8. **Проверка из России**: если работает агент на компьютере в России, его
   данные важнее всего — подтверждённые серверы первыми, заблокированные убираются.

### Рейтинг

- **Quality score** — доля успешных проверок с затуханием (последняя весит
  больше: ×0.75 на каждую более старую из последних 10), ping (медиана
  последних успешных проверок), jitter, число проверок, текущий статус.
- **Stability score** — сильнее опирается на успешность и jitter.
- Подписка набирается по рейтингу с **разнообразием**: один сервер на адрес (хост),
  один на IP выхода, не больше 20 % на одного провайдера (`max_asn_share`).

### Профили (`config/profiles.yaml`)

`top`, `best`, `whitelist` — и любые свои. `aliases` — другие имена файлов с
теми же серверами (старые ссылки не ломаются). `groups: false` в начале файла
отключает подписки по странам и протоколам. Поля: `min_score`, `min_stability`, `max_latency`, `checked_within_hours`,
`seen_within_hours`, `limit`, `countries`, `exclude_countries`, `protocols`,
`require_regions`, `avoid_blocked_in`, `require_tls`, `min_checks`,
`prefer_regions`, `deprioritize_asns`, `per_host`, `per_exit_ip`,
`max_asn_share`, `description`. Основные профили исключают выход в России.
Файл перечитывается без перезапуска.

Clash/Mihomo-подписки (`.yaml`) — полный профиль с группами `SQUAD`
(основная), `AUTO` (url-test — самый быстрый) и `FAILOVER` (fallback —
переход при сбое).

### Сеть пробников

Каждая установка — пробник: GitHub Actions (`gh-actions`) и компьютер
(`<страна>-<6 символов>`). Пробник публикует результаты в свою ветку
`probe-<id>` и забирает отчёты остальных, поэтому у каждого сервера есть статус
по странам: **работает**, **заблокирован** (здесь нет, в другой стране
есть), **не работает**, **нет данных**. Подписки убирают серверы,
заблокированные в России, а подтверждённые из России ставят первыми.

В отчёте только id пробника, его страна и результаты по серверам — без IP и
провайдера. Если на компьютере включён другой VPN, «Авто» видит его страну —
укажи свою в «Настройки → Страна этого компьютера». В режиме «Авто» страна
определяется заново при каждом обновлении серверов; при смене страны у
пробника появляется новый id.

Телефон с SQUAD-VPN.apk тоже может быть пробником (`kind: mobile-whitelist`,
id `mobile-<6 hex>`): он проверяет серверы «Белых списков» только когда
мобильный интернет урезан до белых списков (gstatic.com не открывается, а
ya.ru открывается), и публикует `report.json` в `probe-<id>` через GitHub
API с токеном пользователя. Его результаты попадают в отдельный регион
`RU-WL` и не влияют на статус «RU»; профиль `whitelist` ставит ответившие в
`RU-WL` серверы первыми (`prefer_regions: [RU-WL]`), не ответившие в конец.
Строки подписки телефон сопоставляет с отпечатками серверов по
`fingerprints.json` в ветке `subs` (ключ — первые 16 символов SHA-256
строки без `#имени`). Мобильные «белые списки»
домашний пробник не видит.

## Надёжность и безопасность

- **Доступ.** С этого компьютера ключ не нужен. Из сети нужен ключ с правами
  `sub` (только подписки), `read` (подписки и статистика) или `admin`.
  Управление (VPN, настройки, перезапуск, ключи, копии) — только с этого
  компьютера. Ключи хранятся хешами, сам ключ показывается один раз.
- **Защита локальной панели.** Сервер принимает только запросы на
  `localhost` и IP-адреса (защита от DNS rebinding) и отклоняет изменяющие
  запросы с чужих сайтов (защита от CSRF).
- **Rate limit** из сети: `/sub` — 30 в минуту, `/api` — 120 в минуту на
  адрес; после 10 неверных ключей адрес блокируется на 10 минут.
- **Кэш**: `/sub` — до следующего обновления или 60 с, статистика — 10 с.
- **Резервные копии** базы — раз в сутки, последние 7 (`data\backups`);
  восстановление из приложения или `squad-vpn backup --restore`.
- **Обновления по воздуху (OTA)** — см. ниже.
- **Журналы** (`data\logs`): `squad.log` — сервер (ротация 5×2 МБ),
  `agent.log` — фоновая программа, `server.log` — аварийные сообщения,
  `app.log` — окно, `cli.log` — ошибки команд. Ошибки API — коротким
  понятным текстом, трассировка — в журнале.

### Оформление подписок (для создателей)

Как подписка выглядит у пользователя в приложении (Happ, Hiddify, v2RayTun,
INCY, Streisand, Clash Verge…) задаётся в одном файле
[`config/branding.yaml`](../config/branding.yaml):

- `title` — название подписки (общее и своё для каждой: `profiles: top: title:`);
- `announce` — описание/объявление под названием, можно `{count}` — число серверов;
- `support_url`, `web_page_url` — кнопки «Поддержка» и «Сайт»;
- `update_interval_hours` — как часто приложение обновляет подписку само;
- `node_name` — названия серверов в списке, например `{flag} {country} {n}` →
  «🇩🇪 Германия 1» вместо рекламы чужих каналов; `""` — оставить как есть.

Правится прямо на GitHub (карандаш → «Commit changes»): подписки пересоберутся
через пару минут, а приложения пользователей подтянут новое название при
следующем обновлении подписки. Метаданные передаются строками
`#profile-title:` в начале подписки (для файлов на GitHub) и заголовками
HTTP (для `/sub` с компьютера); текст не на латинице — как `base64:…`.

### Обновления по воздуху

Программа обновляется сама, без пользователя: фоновая программа раз в час
(и по кнопке «Проверить сейчас») смотрит, нет ли новой версии на GitHub.
Обновление ставится, только если оно безопасно:

1. **Прошло проверки на GitHub.** Ставятся только коммиты, у которых
   зелёный CI (тесты и линтер). Если проверки ещё идут — ждём; если упали —
   версия пропускается. Если GitHub молчит дольше 6 часов, работают
   следующие ступени.
2. **Пробный запуск.** Новый код сначала запускается отдельно: импорт всех
   модулей и сборка API. Ошибка — папка сразу откатывается, работающая
   программа даже не останавливается.
3. **Запуск с откатом.** Прежняя версия запускает новую и ждёт до 2,5 минут,
   пока она ответит. Не ответила — новая версия останавливается, папка
   возвращается назад, прежняя версия запускается снова. Плохая версия
   запоминается и больше не ставится.
4. **Только нужные перезапуски.** Если поменялась только документация или
   CI — код обновляется без перезапуска, VPN не моргает.
5. **SQUAD VPN.exe** скачивается из релиза `app-latest` и сверяется с
   `app-manifest.json` (SHA-256 и размер); не совпало — файл выбрасывается.
   Открытое окно предлагает «Перезапустить» в новую версию.
6. **Окно само перезагружается**, когда сервер вернулся с новой версией;
   пока идёт перезапуск — «Обновляюсь… переподключаюсь».

Свои правки и коммиты в папке не трогаются (только «перемотка вперёд»).
История обновлений, причина отката и «Что нового» — в «Настройки →
Обновления по воздуху» (`data\update.json`).

## Приложение для Android

Исходники в `android/` (Kotlin, Jetpack Compose, Material 3). Ядро Xray
(`libv2ray.aar` из AndroidLibXrayLite) читает TUN от `VpnService` своим
tun-инбаундом, поэтому работают все транспорты подписок, включая xhttp.

- Подписки: топ-10, лучшие 100, белые списки или своя ссылка.
- Сервер выбирается сам по реальному пингу; каждые 16 с (при выключенном
  экране раз в 60 с, без обновления уведомления) идёт проверка через ядро,
  после двух промахов подряд приложение переходит на следующий сервер,
  не роняя VPN. При смене Wi-Fi/мобильной сети ядро перезапускается.
- Без выбранного вручную сервера VPN сразу поднимается на последнем
  рабочем сервере этой сети (`Prefs.goodOn`), без пинга; через 1 с две
  проверки через ядро, обе неудачные дают смену сервера.
- Автобелые списки (`core/WhiteLists.kt`): на мобильном интернете, если
  `gstatic.com/generate_204` не открывается напрямую, а `ya.ru` открывается,
  сервис берёт подписку «Белые списки» (`Vpn.autoWhitelist`), и обратно.
  Проверка при подключении, раз в 5 минут на мобильной сети, при смене
  сети и перед сменой сервера после промахов. Подписки «Белые списки» и
  «Своя ссылка» не подменяются.
- Автообход DPI: если при подборе ни один сервер не ответил, ещё 2 группы
  по 12 проверяются с противоположной настройкой фрагментации; что
  сработало, запоминается для сети (`Prefs.dpiOn`, до 20 сетей).
  Переключатель в настройках включает обход везде.
- `bg/RefreshJob.kt`: JobScheduler раз в 6 ч на безлимитной сети и
  зарядке обновляет текущую подписку и «Белые списки», перемеряет
  устаревшие пинги.
- Пинг сервера (`core/Pinger.kt`): сначала TCP-подключение к серверу
  (3 с, кроме hysteria2/kcp/quic и xhttp по h3), только ответившим
  запускается проверка через ядро (`measureOutboundDelay`, не дольше 10 с);
  24 проверки одновременно. При подключении серверы проверяются группами
  по 12: после первого ответа остальным даётся 1,5 с.
- Пинги с телефона хранятся в `pings.json` (ответившие 12 ч, неответившие
  1 ч); при смене сети «мёртвые» забываются. Для каждой сети
  (`core/NetworkId.kt`: оператор по MCC+MNC или шлюз Wi-Fi) в настройках
  хранятся до 5 серверов, которые там работали, они пробуются первыми
  (последний рабочий, если ответил быстрее 1,5 с). В подписке «Белые
  списки» сервер меняется после 3 промахов проверки подряд, в остальных
  после 2. Фоновая проверка после
  подключения перемеряет только замеры старше 30 минут; экран «Серверы»
  сам проверяет всё, если свежих замеров меньше половины, и прячет
  неответившие серверы (переключатель «Скрыть неотвечающие»).
- «Приложения и VPN» (раздельное туннелирование): в режиме «Мимо VPN»
  отмеченные приложения исключаются через `addDisallowedApplication`, в
  режиме «Только эти через VPN» в VPN идут только отмеченные
  (`addAllowedApplication`; пока ничего не отмечено, работает первый режим). Пока список не
  менялся, отмечены банки, Госуслуги, Mir Pay, ЮMoney, Ozon и Wildberries
  (`core/DirectApps.kt`). Список строится из приложений со значком
  (`<queries>` в манифесте); при включённом VPN интерфейс пересоздаётся
  с тем же сервером.
- «Проверка белых списков» (`core/PhoneProbe.kt`): телефон как пробник
  мобильных белых списков, см. «Сеть пробников». По умолчанию выключена,
  нужен токен GitHub с правом `public_repo`.
- Перед сборкой CI гоняет юнит-тесты (`android/app/src/test`): разбор
  ссылок vless/vmess/trojan/ss/hysteria2, конфиг Xray и встроенные
  подписки (каждая должна дать хотя бы один рабочий сервер). Упавший тест
  останавливает сборку, и обновление на телефоны не уходит. Локально:
  `gradle -p android testReleaseUnitTest`.
- Российские сайты (.ru, .su, .рф) по желанию идут напрямую, кроме режима
  белых списков.
- «Обход DPI»: исходящий `freedom` с `fragment` (tlshello, 100–200 байт,
  10–20 мс), прокси идёт через него `sockopt.dialerProxy` (не для
  hysteria/kcp/quic). Kill switch: при обрыве после неудачной смены сервера
  ядро останавливается, а TUN остаётся открытым, пока пользователь не
  переподключится или не нажмёт «Открыть интернет». Тест скорости качает
  до 40 МБ с `speed.cloudflare.com` через SOCKS-порт ядра, до 8 с.
- Виджет (`bg/VpnWidget.kt`), статистика трафика по дням (`traffic.json`,
  62 дня), ключи из буфера обмена в своей подписке, экран первого запуска и
  проверка разрешений (`core/Permissions.kt`).
- Плитка в шторке (с 1.9 её можно добавить кнопкой из настроек через
  `StatusBarManager.requestAddTileService`), автоподключение после
  перезагрузки, системный Always-on VPN. На Android 16 уведомление VPN
  просит повышения до Live Update (`bg/StatusBar.kt`; API Android 16
  вызываются по имени, приложение собирается под Android 15). Суперостров
  HyperOS (`miui.focus.param`) не используется: Xiaomi показывает его только
  приложениям из своего белого списка.
- Сборка: `.github/workflows/build-android.yml` при правке `android/**`.
  APK и манифест уходят в релиз `android-latest` (с 1.5 приложение читает
  `android-manifest-v2.json`, а `android-manifest.json` для 1.4 и старше
  просит переустановить apk), приложение
  проверяет его при каждом запуске и фоновым заданием (JobScheduler) раз в
  4 часа; о новой версии приходит уведомление, а в приложении горит плашка
  «ОБНОВИТЬ». Версия для людей
  в `android/version.properties`, номер сборки берётся из номера запуска CI.
  Каждая версия также получает релиз `android-v<версия>` (не Latest).
  Что нового в каждой версии: `android/CHANGELOG.md`, раздел версии идёт
  в описание релиза.
- В APK встроены подписки top/best/whitelist (CI скачивает их из ветки
  `subs` перед сборкой): если сеть не пускает к GitHub, приложение берёт
  их, пока не скачает свежие.
  Тот же APK кладётся в текущий релиз Latest (`v<версия>` программы для
  Windows), а `build-app.yml` прикладывает его к каждому новому `v<версия>`.
- Интерфейс: Glass MD3 (Compose). Токены дизайна в
  `android/app/src/main/java/com/squad/vpn/ui/glass/Tokens.kt`, компоненты
  (стекло, карточки, кнопки, навигация, шторка, диалог) рядом в `ui/glass/`.
  Размытие фона под стеклом работает на Android 12+, на старых телефонах
  стекло без размытия.
- Кнопка подключения: эмблема SQUAD (`res/drawable-nodpi/connect_button.jpg`).
  Пока VPN подключён, в круге без звука по кругу играет
  `res/raw/connected_loop.mp4` (`ui/LoopVideo.kt`, TextureView + MediaPlayer).
- Подпись (с 1.5): ключ только в секретах репозитория `SQUAD_KEYSTORE_1..4`
  (keystore в base64, разбит на части: один большой секрет GitHub не
  выдаёт задачам) и `SQUAD_KEYSTORE_PASSWORD`, их один раз создаёт workflow
  `apk-signing-key.yml` (нужен секрет `SQUAD_SECRETS_TOKEN`: токен
  с доступом к секретам репозитория, classic со scope repo). Без них apk не собирается.
  Старый ключ до 1.4 был публичным, CI отвергает apk с ним. Если ключ
  сменить, обновление поверх не встанет: apk переустанавливают вручную.

## Справочник

### Команды

```powershell
squad-vpn run [--publish]        # полный цикл один раз
squad-vpn serve [--watch]        # панель и API (+ цикл каждый час)
squad-vpn agent [--stop]         # фоновая программа: панель, цикл, перезапуск, обновления
squad-vpn autostart [--disable]  # автозапуск при входе в Windows и ярлык
squad-vpn app-update             # скачать/обновить SQUAD VPN.exe
squad-vpn doctor [--offline]     # проверить, всё ли в порядке
squad-vpn keys add ИМЯ --scope sub|read|admin / keys list / keys revoke ИМЯ
squad-vpn backup [--list] [--restore ИМЯ]
squad-vpn collect | validate | cleanup | export | publish | smart | probes | sources
squad-vpn setup-mihomo           # скачать ядро Mihomo (Windows, Linux, macOS)
```

`squad-vpn <команда> --help` — все параметры.

### HTTP API

Сервер — `http://127.0.0.1:8080`, документация — `/api/docs`.

| Метод | Описание |
| --- | --- |
| `GET /sub` | подписка: `profile`, `country`, `protocol`, `min_score`, `min_stability`, `max_latency`, `checked_within_hours`, `seen_within_hours`, `limit`, `format=plain\|base64\|mihomo` |
| `GET /health` | статус и версия |
| `GET /api/stats`, `/api/nodes`, `/api/nodes/{fingerprint}` | статистика, серверы (фильтры, сортировка, страницы), история сервера |
| `GET /api/sources`, `/api/profiles`, `/api/probes`, `/api/links`, `/api/cycle`, `/api/agent` | источники, профили, пробники, ссылки, цикл, агент |
| `POST /api/cycle/run` | обновить серверы сейчас (из сети — ключ `admin`) |
| `GET /api/client`, `POST /api/client/{connect,disconnect,failover,choose}`, `GET /api/client/{nodes,events}` | VPN-клиент |
| `GET/POST /api/keys`, `DELETE /api/keys/{имя}` | ключи доступа |
| `GET/POST /api/backups`, `POST /api/backups/{имя}/restore` | резервные копии |
| `GET /api/doctor`, `POST /api/doctor/fix/{restore_proxy,backup_now}` | проверка системы |
| `GET/POST /api/settings`, `GET/POST /api/autostart`, `GET /api/logs`, `POST /api/control/{update,restart,open-folder}` | управление |

Строки с `client`, `keys`, `backups`, `doctor`, `settings`, `autostart`,
`logs`, `control` — только с этого компьютера. `/api/nodes` не отдаёт
учётные данные серверов — они есть только в `/sub`.

### Настройки

- `data\settings.json` — то, что меняется в приложении: интервал, автообновление,
  страна компьютера, профиль и автоподключение VPN, доступ по Wi-Fi.
- `config\squad.yaml` — лимиты, журналы, кэш, копии. Любой параметр
  переопределяется переменной `SQUAD_<РАЗДЕЛ>_<ПАРАМЕТР>`, например
  `SQUAD_LOGGING_LEVEL=DEBUG`.
- `config\profiles.yaml`, `config\sources.yaml` — профили и источники.

### Файлы

| Путь | Что это |
| --- | --- |
| `src/squad_vpn/` | код: сбор, проверка, рейтинг, экспорт, публикация, API, агент, клиент |
| `src/squad_vpn/dashboard/` | панель (`app.html`) и подробная таблица (`index.html`) |
| `app/launcher.py` | SQUAD VPN.exe: окно без рамки со своим заголовком, установщик |
| `install.cmd`, `uninstall.cmd` | установка и удаление автозапуска |
| `data/` | база, журналы, копии, состояние (в Git не попадает) |
| `tools/mihomo/` | ядро Mihomo (скачивается само) |

### Разработка

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
pytest -q
```

CI (`.github/workflows/ci.yml`) гоняет линтер и тесты на Windows; сборка exe —
`.github/workflows/build-app.yml` (на изменения `app/`, на смену версии в
`src/squad_vpn/__init__.py` и на теги `v*`). Сборка обновляет релиз
`app-latest` (оттуда exe обновляется по воздуху) и публикует релиз
`v<версия>` с exe и разделом этой версии из CHANGELOG.md.

Выпуск версии: поднять `__version__` в `src/squad_vpn/__init__.py` и
`version` в `pyproject.toml`, добавить раздел в CHANGELOG.md и строку
«Версия …» в README.md, запушить в `main`.

Удалить автозапуск: `uninstall.cmd` (файлы и база остаются).
